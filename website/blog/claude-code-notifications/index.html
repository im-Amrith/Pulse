Get notified when Claude Code finishes or needs permission.

Claude Code stops and waits when it wants to run a command or has finished the job. If you’ve switched to another window, you don’t find out. Here’s how to get a sound or a desktop notification on Windows and macOS.

Amrithesh S Menon9 November 20266 min read

There are three ways, from least to most setup: a built-in setting, a hook that runs a command, or an app that watches Claude Code for you. All three are free.

1. The built-in setting: preferredNotifChannel

Claude Code has one setting for this, preferredNotifChannel. It decides how Claude Code tells you that a task finished or a permission prompt is waiting. You can change it in a session with /config (it’s listed as Local notifications), or in ~/.claude/settings.json:

{
  "preferredNotifChannel": "terminal_bell"
}

The values:

  • auto (the default): a desktop notification in iTerm2, Ghostty and Kitty; a bell in macOS Terminal only when its audible bell is turned off; nothing in other terminals.
  • terminal_bell: rings the bell in any terminal.
  • iterm2, iterm2_with_bell, kitty, ghostty: that terminal’s own desktop notification.
  • notifications_disabled: nothing.

The catch is in the default: most terminals get nothing. That includes Windows Terminal, the VS Code terminal and Warp. On those, terminal_bell is the easy fix, as long as your terminal’s bell makes a sound. If you want a real notification that shows up wherever you are, use a hook.

2. Hooks: run your own command

Hooks are commands Claude Code runs at fixed moments. Two of them matter here:

  • Notification runs when Claude Code sends a notification. Its notification_type says why: permission_prompt when a tool is waiting for your approval, and idle_prompt about 60 seconds after Claude finished responding, if you haven’t typed since.
  • Stop runs every time Claude finishes responding.

Claude Code passes the event to your command as JSON on standard input. For a permission prompt it looks like this:

{
  "hook_event_name": "Notification",
  "message": "Claude needs your permission to use Bash",
  "notification_type": "permission_prompt",
  "session_id": "…",
  "cwd": "…"
}

Hooks live in ~/.claude/settings.json (for all your projects) or .claude/settings.json in one project. The file is strict JSON: no comments, no trailing commas. If you already have a hooks section, add these events to it instead of making a second one.

macOS

macOS can show a notification from the command line with osascript. This alerts you when Claude needs permission, and when it’s done:

{
  "hooks": {
    "Notification": [
      {
        "matcher": "permission_prompt",
        "hooks": [{ "type": "command", "command": "osascript -e 'display notification \"Claude needs your permission\" with title \"Claude Code\" sound name \"Glass\"'" }]
      }
    ],
    "Stop": [
      {
        "hooks": [{ "type": "command", "command": "osascript -e 'display notification \"Done\" with title \"Claude Code\"'" }]
      }
    ]
  }
}

Prefer just a sound? Use afplay /System/Library/Sounds/Glass.aiff as the command. If no notification appears, check System Settings → Notifications: notifications from osascript show up under Script Editor, and they need to be allowed there.

Windows

On Windows, a few lines of PowerShell can show a notification. Save this as notify.ps1 in your .claude folder (C:\Users\you\.claude\notify.ps1). It shows Claude’s own message when there is one:

# Shows a Windows notification for Claude Code. Claude Code passes the event as JSON on stdin.
$e = [Console]::In.ReadToEnd() | ConvertFrom-Json
$text = if ($e.message) { $e.message } else { 'Claude Code is done' }
Add-Type -AssemblyName System.Windows.Forms, System.Drawing
$n = New-Object System.Windows.Forms.NotifyIcon
$n.Icon = [System.Drawing.SystemIcons]::Information
$n.Visible = $true
$n.ShowBalloonTip(5000, 'Claude Code', $text, 'Info')
Start-Sleep -Seconds 6
$n.Dispose()

Then point both hooks at it. Put in your own user name, keep the forward slashes, and keep the \" quotes around the path: they matter if your user name has a space in it.

{
  "hooks": {
    "Notification": [
      {
        "matcher": "permission_prompt",
        "hooks": [{ "type": "command", "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"C:/Users/you/.claude/notify.ps1\"" }]
      }
    ],
    "Stop": [
      {
        "hooks": [{ "type": "command", "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"C:/Users/you/.claude/notify.ps1\"" }]
      }
    ]
  }
}

To test it before Claude does, run this in PowerShell. A notification should appear in the corner of your screen:

'{"message":"Test from Claude Code"}' | powershell -NoProfile -ExecutionPolicy Bypass -File "$HOME/.claude/notify.ps1"

Nothing appears? Turn off Do not disturb (Focus Assist on Windows 10), and check that notifications are on in Settings → System → Notifications.

Things that trip people up

  • Start a new session after editing settings.json, so Claude Code picks up the hooks.
  • Stop fires after every reply, including short ones. If that’s too much, use the Notification hook with idle_prompt instead: it only fires once Claude has been waiting on you for about a minute.
  • tmux swallows terminal notifications unless set -g allow-passthrough on is in ~/.tmux.conf. Hooks aren’t affected, because they don’t go through the terminal.

3. Or let an app watch Claude Code for you

A notification tells you that Claude needs you. You still have to switch back to the terminal to see what it wants and answer it. That round trip is why I built Pulse.

Pulse is a small island at the top of your screen, on Windows and Mac. Under the hood it uses the same hooks as above, sent to an address on your own computer, so nothing leaves your machine. On top of the alert, it:

  • shows what Claude is doing right now (reading a file, editing, running a command), with a diff of the edit
  • shows the permission request itself, with Allow and Deny buttons, so you can answer from wherever you are
  • smiles when the job is done, and shows your 5-hour usage with a countdown to the reset

It’s free and open source (MIT), with no account. Choose Connect in the island and it adds its hooks to your settings.json, next to any you already have; Disconnect removes only its own. If you’re curious how it holds a permission request until you answer, I wrote that up in How Pulse sits between Claude Code and your Allow button.

Which one should you use?

  • You use iTerm2, Ghostty or Kitty: you already get notifications with the default setting.
  • You want a beep and nothing else: set preferredNotifChannel to terminal_bell.
  • You want a desktop notification on any terminal: the hooks above.
  • You want to see and answer what Claude is asking without switching windows: Pulse.
